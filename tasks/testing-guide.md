## 测试场景 1: 参数化部署

### 目标
验证动态参数表单生成和参数注入功能

### 前置条件
确保 `packages/nginx/1.28.0/metadata.json` 存在并包含参数定义

### 测试步骤

1. **导航到部署页面**
   - 点击左侧菜单 "部署管理"

2. **创建新部署**
   - 点击 "新建部署" 按钮
   - 部署类型: 选择 "离线包"
   - 目标服务器: 选择任意服务器
   - 离线包: 选择 "nginx-1.28.0"

3. **验证参数表单渲染**
   - ✅ 应该看到动态生成的参数表单
   - ✅ 应该包含 7 个参数（根据 metadata.json）
   - ✅ 参数分为"基础参数"和"高级参数"两组
   - ✅ 每个参数显示默认值

4. **修改参数**
   - 修改 "监听端口" 从 80 改为 8080
   - 修改 "工作进程数" 从 auto 改为 4
   - 启用 "启用 Gzip 压缩"

5. **提交部署**
   - 点击 "确定" 创建部署
   - 点击 "执行" 按钮开始部署

6. **验证参数注入**
   - 查看实时日志
   - ✅ 日志中应显示自定义参数值
   - ✅ 脚本应使用 PORT=8080 而非默认的 80
   - ✅ 脚本应使用 WORKER_PROCESSES=4

### 预期结果
- 参数表单正确渲染所有参数类型（string, number, boolean, select）
- 参数验证规则生效（必填、最小值、最大值等）
- 参数正确传递到部署脚本并在日志中可见

## 测试场景 2: 实时日志和取消部署

### 目标
验证 SSE 实时日志流和部署取消功能

### 测试步骤

1. **创建部署任务**
   - 创建任意离线包部署（nginx 或 redis）
   - 点击 "执行" 开始部署

2. **验证实时日志**
   - ✅ 日志应实时流式显示，无需刷新页面
   - ✅ 每条日志带时间戳
   - ✅ 日志按时间顺序显示
   - ✅ 无明显延迟（< 1秒）

3. **测试取消功能**
   - 在部署执行过程中点击 "取消" 按钮

   - ✅ 状态从 "running" 变为 "cancelled"
   - ✅ 日志显示 "部署已取消" 消息
   - ✅ 取消按钮变为不可用

4. **验证状态持久化**
   - 刷新页面
   - ✅ 部署状态仍为 "cancelled"
   - ✅ 日志内容保留

### 预期结果
- 实时日志流畅无卡顿
- 取消操作立即生效
- 状态更新正确反映到 UI
- 数据库正确记录取消状态

## 测试场景 3: Nginx 配置应用

### 目标
验证 Nginx 配置应用到服务器的完整流程

### 前置条件
- 至少有一个已配置的服务器
- 服务器上已部署 Nginx

### 测试步骤

1. **创建 Nginx 配置**
   - 导航到 "Nginx 配置" 页面
   - 点击 "新建配置"
   - 配置名称: `test-config`
   - 配置内容:
     ```nginx
     server {
         listen 8080;
         server_name test.example.com;
         location / {
             return 200 "Test Config Applied";
         }
     }
     ```
   - 点击 "确定" 保存

2. **应用配置到服务器**
   - 在配置列表中找到 `test-config`
   - 点击 "应用配置" 按钮
   - ✅ 应该弹出 ApplyConfigModal 对话框

3. **配置应用选项**
   - 目标服务器: 选择已部署 Nginx 的服务器
   - ✅ 部署路径应自动填充（如 `/usr/local/nginx`）
   - 配置文件路径: 使用默认值或自定义
   - 启用备份: 勾选
   - 执行配置测试: 勾选
   - 重启服务: 勾选

4. **提交应用**
   - 点击 "确定" 开始应用
   - ✅ 应该创建一个新的部署任务
   - ✅ 自动跳转到部署详情页

5. **验证应用过程**
   - 查看实时日志
   - ✅ 应显示备份原配置文件
   - ✅ 应显示上传新配置文件
   - ✅ 应显示执行 `nginx -t` 测试
   - ✅ 应显示重启 Nginx 服务
   - ✅ 部署状态变为 "success"

6. **查看应用历史**
   - 返回 "Nginx 配置" 页面
   - 点击 `test-config` 查看详情
   - 切换到 "应用历史" 标签
   - ✅ 应显示刚才的应用记录
   - ✅ 记录包含服务器、时间、状态等信息

### 预期结果
- ApplyConfigModal 正确显示服务器列表
- 部署路径自动填充功能正常
- 配置应用流程完整执行
- 备份、测试、重启步骤都正确执行
- 应用历史正确记录

## 测试场景 4: 部署类型验证

### 目标
确认 nginx_config 部署类型已移除

### 测试步骤

1. **检查部署创建对话框**
   - 导航到 "部署管理" 页面
   - 点击 "新建部署"
   - 查看 "部署类型" 下拉选项
   - ✅ 应该只有两个选项: "离线包" 和 "证书"
   - ✅ 不应该有 "nginx_config" 选项

2. **检查现有部署**
   - 查看部署列表
   - ✅ 所有部署的类型应该是 "package" 或 "certificate"
   - ✅ 不应该有 "nginx_config" 类型的部署

### 预期结果
- nginx_config 选项已从 UI 中完全移除
- 现有部署不受影响

## 测试场景 5: 错误处理

### 目标
验证各种错误场景的处理

### 测试步骤

1. **参数验证错误**
   - 创建部署时留空必填参数
   - ✅ 应显示验证错误提示
   - ✅ 不允许提交

2. **SSH 连接失败**
   - 创建部署到不可达的服务器
   - ✅ 应显示连接错误
   - ✅ 部署状态变为 "failed"
   - ✅ 日志显示错误详情

3. **配置测试失败**
   - 应用无效的 Nginx 配置
   - ✅ nginx -t 应该失败
   - ✅ 部署状态变为 "failed"
   - ✅ 原配置不应被覆盖（备份生效）

### 预期结果
- 所有错误都有清晰的提示信息
- 错误不会导致系统崩溃
- 失败的操作可以回滚
